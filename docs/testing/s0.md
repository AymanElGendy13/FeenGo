Status values:

- **pass**: the test exists and runs in CI.
- **missing**: it should exist and does not.
- **blocked**: it needs an increment that is not built yet, or an owner answer. C6 needs question 11; C7 needs question 12; C8 and C9 wait only on build order; C10 needs question 16. Question numbers are those in `docs/ARCHITECTURE.md` section 22. Increments are built strictly in order (ARCHITECTURE section 3), so each one also waits on the one before it.
- **manual**: proved by a manual check in section 5, not by CI.
- **planned**: an end-to-end or contract test that qa-tester writes in C11 (section 3 below).

API test files are under `apps/api/`, token tests under `packages/design-tokens/test/`. Test names are quoted exactly; `%s` marks a parameterised name, and `›` joins a `node --test` suite name to its test name.

## 6. Gaps

Acceptance checks with no test planned anywhere:

1. **Q-02 minimum versions.** Nothing runs the app on iOS 15 or Android 8. The real phones prove only their own versions, and C10 builds for iOS without running it. Android is covered if the e2e emulator uses API 26 (section 3 proposal). iOS 15 has no route.
2. **Q-04 contrast on real screens.** The token check covers declared pairs only. Nothing checks that screens use only those pairs. An accessibility scan in Playwright would need a new dependency, which needs the owner's approval.
3. **Q-05 secrets.** Secret scanning with push protection is an owner repository setting, not a CI job (sections 19.3 and 21), and is not yet confirmed (row 51, M-4). K-5, if approved, would check the image for a `.env` file.
4. **C1 Compose health** has no CI step (row 5); section 3 gives C1 no CI job. M-5 covers it by hand; a Compose CI step is a proposal for release-manager.
5. **CI gates never shown to fail.** Nothing proves that the stale-types step, the stale-token step or the Redocly rules fail on bad input. Each needs one recorded failing run. The contrast gate is the exception: `the build writes nothing when a pair fails` proves it fails.
6. **Database lost after start-up** (row 11): no test.
7. **Hard-coded user-facing text.** The translation checks compare keys between languages, but nothing catches text written inline in code (CLAUDE.md rule).
8. **Health rate-limit ceilings.** `x-rate-limit` is declared on `/health` and `/health/ready`, but the rate limiter is S1 (section 7.4). Nothing enforces or tests the ceiling in S0.
